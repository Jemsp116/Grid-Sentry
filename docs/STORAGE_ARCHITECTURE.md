# Grid Sentry — Complete Storage & Data Persistence Map

This document provides a single-source-of-truth inventory of **every storage location, database, collection, search index, local file, client storage, and cryptographic secret** used by the Grid Sentry application.

---

## 1. High-Level Storage Architecture Overview

Grid Sentry employs a **hybrid, multi-tier storage model** designed for security operations:
1. **Primary Central Database (MongoDB 7.0)** — Relational/structural metadata (users, sessions, rules, alerts, blocklist, audit trail, API keys).
2. **SIEM Analytics Engine (OpenSearch 2.x)** — High-velocity, full-text indexed log telemetry (`soc-logs-*`) evaluated by the detection worker.
3. **Tenant Private Database (BYODB MongoDB)** — Optional customer-owned MongoDB instance where raw website/application telemetry (`source_logs`) and isolated tenant metadata are written.
4. **Local Host / Container File Storage** — GeoIP location database, container volume mounts, and shipper configurations.
5. **Browser Client Storage** — Ephemeral session scoping, secure httpOnly cookie tokens, and in-memory authorization state.
6. **Cryptographic Vault** — Salted bcrypt hashes, SHA-256 token/key digests, and AES-256-GCM KMS encryption for customer database strings.

## 3. SIEM Log Telemetry Store: OpenSearch 2.x

High-velocity log telemetry streams into the central OpenSearch cluster via Vector or the `/api/logs/ingest` REST endpoint.

- **Index Pattern**: `soc-logs-YYYY-MM` (automatically rotated with Index Lifecycle Management).
- **Index Aliases**: `soc-logs`
- **Fields Stored per Document**:
  - `@timestamp` / `timestamp` (`date`): ISO-8601 event time.
  - `source_ip` (`ip` or `keyword`): Originating IPv4/IPv6 address.
  - `ssh_user` / `user_identifier` (`keyword`): User identity, login account, or email.
  - `log_source` (`keyword`): The application/system identifier (e.g. `ssh_auth`, `cyber`, `web-portal`).
  - `event_type` (`keyword`): Standardized event classification (e.g. `user_login_failed`, `page_view`, `agent_connected`).
  - `outcome` (`keyword`): Categorical result (`success`, `failure`, `blocked`).
  - `raw_message` (`text` + `keyword`): Full-text indexed human-readable syslog message.
  - `host` (`keyword`): Generating server or hostname.
  - `details` (`object`): Arbitrary unstructured JSON metadata payload.

## 4. Tenant Private Database: Bring Your Own Database (BYODB)

When an organization connects their own MongoDB instance (configured in `/settings/database`):

- **Database Connection Management**:
  - Encrypted connection string decrypted in-memory using AES-256-GCM (`kmsEncryption.ts`).
  - Connection pool managed dynamically via `tenantConnectionManager.ts`.
- **Tenant-Side Collections**:
  - **`source_logs`** (declared in `tenantData.service.ts`):
    - Stores the **raw website/application telemetry** sent from the client's connected apps.
    - Fields: `timestamp`, `event_type`, `source_ip`, `user_identifier`, `raw_message`, `source_id`, `app_name`, `org_id`, `details`, `created_at`.
    - Indexes: `{ app_name: 1, timestamp: -1 }`, `{ source_id: 1, timestamp: -1 }`.
    - Accessed by the **Log Explorer (Mode B)** via `GET /api/logs/tenant-source-logs`.
  - **Tenant Structured Data** (managed via `tenantDataAccess.ts`):
    - When full tenant isolation is activated, `alerts`, `rules`, and `audit_log` records are written directly into the tenant's private database.

## 6. Browser Client-Side Storage

| Storage Mechanism | Key / Name | Scope & Lifetime | Data Contained | Security Attributes |
| :--- | :--- | :--- | :--- | :--- |
| **`sessionStorage`** | `gs_selected_source` | Current tab session; cleared on tab close | Active connected source ID (e.g. `1`, `2`, or sentinel `__all__`). | Preserves analyst source-scoping context across Overview, Alert Feed, and Log Explorer. |
| **HTTP Cookie** | `refreshToken` | 7 days; persisted in browser cookie jar | Raw refresh token string. | `httpOnly: true`, `SameSite=Strict`, `Path=/api/auth`. Inaccessible to client JavaScript (immune to XSS). |
| **React Memory State** | `AuthContext` | Current browser page lifecycle | Short-lived JWT `accessToken` (15 min), user ID, email, and role. | Kept strictly in memory; never written to `localStorage` to prevent token theft. |
| **React Memory State** | `SourceContext` | Current browser page lifecycle | Cached list of active connected project API keys (`ApiKeyItem[]`). | Prevents redundant `/api/keys` fetches across page navigation. |

## 7. Cryptographic & Secret Storage

| Secret / Credential | Storage Location | Encryption / Hashing Algorithm | Exposure & Access Policy |
| :--- | :--- | :--- | :--- |
| **User Passwords** | `users.password_hash` | **bcrypt** (12 salt rounds) | Never decrypted; validated via `bcrypt.compare()`. Never returned in API responses. |
| **Shipper / SDK API Keys** | `api_keys.key_hash` | **SHA-256** hex digest | Raw key (`gs_live_...`) is displayed **once** to the admin at creation, then discarded. API requests hash incoming header and compare against DB. |
| **Refresh Tokens** | `refresh_tokens.token_hash` | **SHA-256** hex digest | Raw token sent to client as httpOnly cookie. Database stores only the hash; compromise of DB does not leak active tokens. |
| **Team Invite Tokens** | `invitations.token` | **SHA-256** hex digest | Single-use invitation link contains the raw token; backend compares hash upon acceptance. |
| **BYODB Connection Strings** | `tenant_databases.encrypted_connection_string` | **AES-256-GCM** Authenticated Encryption | Encrypted with initialization vector (IV) and authentication tag. Decrypted only in memory when acquiring connection pool. Never logged in errors. |
| **JWT Signing Secrets** | Server Environment (`.env`) | HMAC-SHA256 (`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`) | Distinct secrets used for access vs refresh tokens. Stored only on server environment. |

## 8. Summary Checklist for Operators & Auditors

- [x] **No Plaintext Passwords**: Every user password is encrypted using 12-round bcrypt.
- [x] **No Plaintext API Keys**: Stored as one-way SHA-256 hashes.
- [x] **No Client-Side Token Storage**: Access tokens live strictly in memory; refresh tokens in httpOnly cookies.
- [x] **Tenant Database Isolation**: External customer MongoDB credentials are encrypted with AES-256-GCM authenticated encryption.
- [x] **Dual Telemetry Flow**: High-scale analytics in OpenSearch; private raw website events in tenant's own MongoDB `source_logs`.
